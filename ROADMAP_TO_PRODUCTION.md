# Roadmap to Production

Что нужно довести решение (Gantt AI Plan) до боевого состояния: сознательные
технические долги, чего не хватает, риски и порядок закрытия.

---

## 1. Текущее состояние (MVP, тестовое задание)

- Backend FastAPI + in-process MCP (SDK 2.0) + LLM-агент (two-pass) — работает.
- Frontend React 19 + Vite 8 + Tailwind v4: Гант, модалка, чат с SSE, подтверждение.
- Scheduler: топосорт + критический путь (CPM) + каскад + защита от циклов.
- Excel import/export (`data_only`, без формул/макросов).
- **28 автотестов**, все проходят.
- **Развёрнуто** на VM (95.142.46.44:8080), Docker Compose, **GitHub Actions CI/CD**
  (pytest + SSH-deploy).
- **Персистентность сессии** — `session_id` в `localStorage` браузера: правки
  сохраняются при перезагрузке (пока сессия жива на бэкенде, TTL 30 мин).
- **НЕ в проде**: нет постоянной БД (переживает рестарт контейнера), нет
  аутентификации, LLM — live Gemini (free tier) или fallback.

## 2. Сознательно оставленные технические долги

| # | Долг | Почему оставлен (сознательно) | Стоимость закрытия |
|---|---|---|---|
| D-1 | **In-memory Store** (`SessionStore`, TTL/LRU) вместо БД | MVP держит план в памяти; простота, не нужны миграции | Переписать на PostgreSQL + Redis (или SQLite-FTS) |
| D-2 | **Undo в памяти** (cap 20 снапшотов) | Хватит для демо-сценария; дешёвый | Перенести в БД + audit log |
| D-3 | **SSE через простой генератор** (без уведомлений подрядчиков) | Демо однопользовательское | Пром. SSE с reconnect/event-id/keepalive |
| D-4 | **Нет аутентификации/авторизации** | Для тестового задания не нужно | Сессии + JWT/OAuth, RBAC |
| D-5 | **LLM fallback вместо полноценного** | Даже без ключа продукт работает (демо/тесты) | Подключить реальный LLM-ключ, промпты, eval-набор |
| D-6 | **Нет телеметрии/логирования** | MVP | Prometheus + OpenTelemetry + централизованный лог |
| D-7 | **Один процесс (in-process MCP)** | Арх. решение: гибкий вынос | Вынести MCP в отдельный процесс/сервис без смены контракта |
| D-8 | **Нет rate-limit / анти-DDoS от LLM-вызовов** | — | Rate-limit на /api/chat, лимит токенов на сессию |

## 2. Чего не хватает для продакшена

1. **Постоянная БД** — сейчас in-memory (D1) + localStorage на фронте; данные
   теряются при рестарте контейнера. Для проде — PostgreSQL/SQLite на бэкенде.
2. **Безопасность многопользовательскости** — нет изоляции сессий между пользователями.
3. **Валидация входного Excel** — расширить: выбор листа, типы, маппинг колонок
   со синонимами, обработка формул (сейчас `data_only=True`).
4. **Расширенный движок сроков** — сейчас рабочие дни = календарные; нет
   выходных/праздников, зависимостей по типам (SS/FF/SF), ресурсного планирования.
5. **Тестирование стриминга под нагрузкой** — много одновременных SSE-подключений.
6. **Качество live-LLM** — Gemini free tier медленный/rate-limited; для прода —
   надёжный провайдер с ключом и eval-набором русских промптов.

## 3. Риски

| Риск | Вероятность/влияние | Митигация |
|---|---|---|
| R-1 Собственная VM: uptime зависит от хоста/сети (95.142.46.44) | Низкая/Средняя | Docker `restart: unless-stopped`, health-check, мониторинг |
| R-2 LLM качество разбора русского языка (двусмысленности: «на 2 дня» = сдвиг/дата) | Средняя/Высокая | Два прохода (intent), плюс меню подтверждения и `undo`; eval-набор |
| R-3 Расчёт критического пути — confusion с end/start-границами | Низкая | Юнит-тесты CPM; ручная проверка на seed плане |
| R-4 Граф зависимостей с циклами | Низкая | Детект циклов в `scheduler`, блокировки `set_dependency` |
| R-5 Гигантские Excel (лимит 100k ячеек) | Низкая | Пред-валидация, лимит размера/ячеек, ошибка 413/400 |
| R-6 Секьюрити: формулы/macros в Excel | Низкая | `data_only=True`, чистый CSV, нет `eval` |
| R-7 Gemini free tier (медленный, rate-limited) | Средняя | Фолбэк на детерминированный парсер; для прода — платный провайдер |

## 4. Порядок закрытия (очередь)

**Уже сделано:**
- Деплой на VM (95.142.46.44:8080), Docker Compose, GitHub Actions CI/CD.
- Персистентность сессии через localStorage (правки переживают перезагрузку).

**Дальше (очередь):**
1. **Постгрес-персистентность** — заменить in-memory store (D-1), чтобы план
   переживал рестарт контейнера и был доступен по постоянному id.
2. **Аутентификация + изоляция сессий** (D-4) — перед многопользовательским режимом.
3. **LLM-интеграция в продакшене** (D-5) — надёжный провайдер с ключом,
   промпт-параметры, лимиты, eval-набор.
4. **SSE-надёжность** (D-3): keepalive, reconnect/backoff, metrics.
5. **Мониторинг и логирование** (D-6).
6. **Расширение движка сроков** (календарь, типы зависимостей) — прод-фичи.
