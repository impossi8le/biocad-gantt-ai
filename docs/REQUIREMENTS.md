## 1. Цель

Разработать локально разворачиваемый fullstack AI-агент «Научный помощник» для исследователя в области биоинформатики / медицины. Приложение позволяет:
- загружать научные статьи в PDF и индексировать их в векторной БД;
- вести RAG-диалог с коллекцией статей с обязательными ссылками на источники;
- получать структурированное саммари каждой статьи;
- видеть аналитический дашборд по коллекции (количество, тематики, динамика загрузок, ключевые термины).

Успех измеряется тем, что проверяющий выполняет `docker-compose up`, открывает `http://localhost:3000`, загружает 3–5 PDF из `samples/` и за 5–10 минут воспроизводит все четыре экрана без дополнительных ручных действий.

## 4. Use Cases

### UC-1. Загрузка и индексация PDF
**Актор:** Исследователь, Система индексации.
**Предусловие:** Приложение запущено, БД и Qdrant доступны.
**Основной поток:**
1. Пользователь перетаскивает PDF на экран «Библиотека» или нажимает «Загрузить».
2. Frontend отправляет файл(ы) `POST /api/articles/upload` (multipart).
3. Backend сохраняет файл в `./data/uploads/`, вычисляет SHA-256, создаёт запись `Article(status='uploaded')`.
4. Backend ставит задачу индексации (in-process background task).
5. Система: парсит PDF (pypdf + fallback pdfplumber), извлекает метаданные (title/authors/year), разбивает на чанки (≈500 токенов, overlap 15%), считает эмбеддинги, пишет в Qdrant, обновляет статус на `indexed`.
6. Frontend через polling `GET /api/articles/{id}` или SSE показывает смену статуса.

**Альтернативные потоки:**
- **A1. Дубликат:** SHA-256 уже есть → HTTP 409 + `existing_article_id`, UI предлагает открыть существующую.
- **A2. Битый PDF:** парсер падает → статус `failed`, в БД сохраняется `error_message`, UI показывает красный бейдж с текстом ошибки и кнопкой «Удалить».
- **A3. PDF без текстового слоя:** извлечено < 50 символов → статус `failed` с сообщением «Требуется OCR — не поддерживается в MVP».
- **A4. LLM/эмбеддер недоступен:** задача откладывается с экспоненциальным retry (3 попытки), затем `failed` с пояснением.
- **A5. Превышен размер:** > 50 MB → HTTP 413, отказ до записи в БД.

**Постусловие:** статья в статусе `indexed` доступна для RAG, саммари и аналитики.

### UC-2. RAG-чат с цитатами
**Актор:** Исследователь, LLM-провайдер.
**Предусловие:** в коллекции ≥ 1 статья в статусе `indexed`.
**Основной поток:**
1. Пользователь открывает экран «Чат», вводит вопрос, нажимает Send.
2. Frontend открывает SSE-соединение `POST /api/chat/stream` (body: question, optional `article_ids[]`, `session_id`).
3. Backend: эмбеддит вопрос → `qdrant.search(top_k=6, filter по article_ids)` → собирает контекст из чанков (с метаданными `article_id, page, chunk_idx`) → строит промпт с системной инструкцией «отвечай только по контексту, цитируй [n]» → стримит токены от LiteLLM → пересылает клиенту.
4. По завершении backend возвращает `sources: [{article_id, title, page, snippet}]`.
5. Frontend рендерит ответ с подсвеченными ссылками `[1]`, `[2]`, …; клик → модалка/панель с фрагментом и переходом к статье.

**Альтернативные потоки:**
- **A1. Пустая коллекция:** HTTP 400 «No indexed articles», UI показывает empty-state со ссылкой на «Библиотеку».
- **A2. LLM недоступен:** SSE-шлёт `event: error` с кодом, UI показывает inline-баннер, вопрос сохраняется в истории как неотвеченный.
- **A3. Нет релевантных чанков (score < threshold):** backend отвечает честно «В загруженных статьях информации не найдено», sources = [].
- **A4. Таймаут LLM (>60 c):** обрыв стрима, частичный ответ помечается как «прервано».

**Постусловие:** пара «вопрос-ответ» сохранена в `chat_messages`, источники связаны через FK.

### UC-3. Генерация саммари
**Актор:** Исследователь.
**Предусловие:** статья в статусе `indexed`.
**Основной поток:**
1. Пользователь из карточки статьи нажимает «Саммари».
2. Frontend: `GET /api/articles/{id}/summary`.
3. Если в БД есть `summary` и флаг `fresh` — вернуть закэшированное.
4. Иначе backend: берёт первые N чанков + чанки из разделов «Abstract/Conclusion» (эвристика по заголовкам), отправляет в LLM с промптом-шаблоном → получает структурированный JSON `{objective, methods, results, conclusions, key_terms[]}` → сохраняет в БД → возвращает.
5. Frontend рендерит секции карточками.

**Альтернативные потоки:**
- **A1. Статья не indexed:** HTTP 409 «Сначала дождитесь индексации».
- **A2. LLM недоступен:** HTTP 503, UI показывает ошибку с кнопкой «Повторить».
- **A3. Перегенерация:** `POST /api/articles/{id}/summary/regenerate` — инвалидирует кэш, повторяет шаг 4.

### UC-4. Дашборд аналитики
**Актор:** Исследователь.
**Предусловие:** хотя бы одна статья загружена (для непустых графиков).
**Основной поток:**
1. Пользователь открывает «Аналитика».
2. Frontend параллельно запрашивает:
   - `GET /api/analytics/overview` → counts (articles, chunks, total_bytes, avg_pages);
   - `GET /api/analytics/timeline?days=30` → uploads per day;
   - `GET /api/analytics/top-terms?limit=10` → агрегация по ключевым терминам саммари/чанков;
   - `GET /api/analytics/by-year` → распределение по году публикации.
3. Backend считает агрегации SQL-запросами по PostgreSQL (без обращения к LLM).
4. Frontend рендерит виджеты: StatBlock, LineChart, BarChart, TagCloud (в токенах DESIGN.md).

**Альтернативные потоки:**
- **A1. Пустая коллекция:** все виджеты показывают empty-state с иконкой и подсказкой.
- **A2. Клик по термину:** переход `/chat?prefill=<термин>` — чат открывается с предзаполненным input.

### UC-5. Обработка ошибок (сводный)

| Сценарий | Поведение системы | UI |
|---|---|---|
| Битый PDF | статус `failed`, error_message в БД, чанки не создаются | Красный бейдж + tooltip с текстом + кнопка «Удалить» |
| Дубликат по SHA-256 | HTTP 409 + ссылка на существующую | Модалка «Статья уже в библиотеке. Открыть?» |
| LLM API 5xx / timeout | Retry ×3 с backoff, затем `failed` / SSE-error | Баннер «LLM недоступен», retry-кнопка |
| LLM API 401 (неверный ключ) | Без retry, явная ошибка конфигурации | Баннер «Проверьте OPENAI_API_KEY в .env» |
| Qdrant недоступен | Health-check в `/healthz` → degraded | Глобальный баннер «Vector DB offline» |
| PostgreSQL недоступен | FastAPI стартует, но `/healthz` → 503 | Frontend показывает splash «Backend offline» |
| Пустая коллекция | Чат возвращает 400 | Empty-state + CTA «Загрузить статью» |
| Превышение max_tokens в чате | Truncation контекста до 6 чанков × 500 токенов | Незаметно для пользователя |

## 5. Функциональные требования (FR)

### 5.1. Ingestion (загрузка)
- **FR-1.** `POST /api/articles/upload`: multipart, 1–10 PDF, каждый ≤50 МБ, MIME `application/pdf` + проверка magic bytes `%PDF`.
- **FR-2.** SHA-256 каждого файла; совпадение → HTTP 409 + `existing_article_id`.
- **FR-3.** Хранение файла как `./data/uploads/<sha256>.pdf` (content-addressable).
- **FR-4.** Извлечение `title/authors/year` из PDF-метаданных + эвристики первой страницы; nullable.
- **FR-5.** Статус-машина `uploaded → parsing → chunking → embedding → indexed | failed`, переходы с timestamps.

### 5.2. Indexing
- **FR-6.** Парсинг pypdf, fallback pdfplumber. OCR вне MVP.
- **FR-7.** Чанки: recursive splitter, ~500 токенов, overlap ~75 (≈15%), разделители `\n\n / \n / ". " / " "`.
- **FR-8.** Атрибуты чанка: `chunk_id, article_id, page_start, page_end, chunk_idx, text, token_count`.
- **FR-9.** Эмбеддинги через LiteLLM `text-embedding-3-small` (dim=1536) либо локально sentence-transformers (`.env: EMBEDDINGS_PROVIDER`).
- **FR-10.** Qdrant-коллекция `articles_chunks`; payload `{article_id, page, chunk_idx}`.
- **FR-11.** Идемпотентность: перед повторной вставкой удаляются старые векторы статьи.

### 5.3. RAG / Chat
- **FR-12.** `POST /api/chat/stream`: `{question, session_id?, article_ids?, top_k=6}` → SSE `token|sources|done|error`.
- **FR-13.** Системный промпт: отвечать только по контексту, цитировать `[1]…[n]`, при отсутствии данных — «Информация не найдена».
- **FR-14.** Retrieval: `qdrant.search(top_k, filter=article_ids, score_threshold≈0.3)`.
- **FR-15.** Контекст: топ-k чанков с префиксом `[n] (Article "Title", p.X): …`, суммарно ≤6000 токенов.
- **FR-16.** История сессии: последние 4 пары Q/A в контексте.
- **FR-17.** Персист: `chat_messages` + `chat_message_sources` (FK).

### 5.4. Summary
- **FR-18.** `GET /api/articles/{id}/summary` → `{objective, methods, results, conclusions, key_terms[], generated_at}`, кэш в БД.
- **FR-19.** `POST /api/articles/{id}/summary/regenerate` — инвалидация + перегенерация.
- **FR-20.** Строгий JSON (JSON mode); невалид → 1 retry, затем ошибка.
- **FR-21.** Саммари только для статуса `indexed`.

### 5.5. Analytics (только SQL, без LLM)
- **FR-22.** `GET /api/analytics/overview` → `{articles_total, articles_indexed, articles_failed, chunks_total, total_bytes, avg_pages}`.
- **FR-23.** `GET /api/analytics/timeline?days=N` → `[{date, uploads_count}]` (default 30).
- **FR-24.** `GET /api/analytics/top-terms?limit=N` → `[{term, frequency}]` из `key_terms` (fallback TF-IDF по чанкам).
- **FR-25.** `GET /api/analytics/by-year` → `[{year, count}]`.

### 5.6. UI (4 экрана + DESIGN.md)
- **FR-27.** `/` Чат: панель сессий слева, лента сообщений, input + Send, индикатор «печатает…».
- **FR-28.** `/library`: таблица/сетка, DnD-зона, фильтры, поиск, действия (Саммари/Скачать/Удалить).
- **FR-29.** `/articles/{id}/summary`: метаданные + 5 секций + «Копировать markdown»/«Перегенерировать»/«Назад».
- **FR-30.** `/analytics`: 4 виджета.
- **FR-31.** Строгое соответствие DESIGN.md: токены `#f5f5f5/#fafafa/#ffffff/#0a0a0a/#171717/#737373/#e5e5e5/#e7000b`; Geist; радиусы 18px (интерактив)/24px (карточки); `#e7000b` — только destructive/error; Tailwind v4 + `@theme` из DESIGN.md.
- **FR-32.** Каждый экран: loading skeleton, empty state с CTA, error state с retry.
- **FR-33.** Desktop-first, max-width 1280px, адаптив 768–1920px.

### 5.7. Export
- **FR-34.** Копирование ответа чата (plain + markdown с цитатами).
- **FR-35.** Копирование саммари в markdown.
- **FR-36.** (P2) Экспорт аналитики в CSV.

### 5.8. Ops / Deliverables
- **FR-37.** `docker-compose up` поднимает `db`, `qdrant`, `backend`, `frontend`. Конфиг — `.env.example`.
- **FR-38.** `GET /healthz` — агрегат БД + Qdrant + LLM.
- **FR-39.** README.md: quickstart, стек, скриншоты 4 экранов, 3–5 примеров Q&A, раздел «Дизайн-система» со ссылкой на `DESIGN.md`.
- **FR-40.** ARCHITECTURE.md ≤500 слов, ASCII-диаграмма, обоснование Qdrant.
- **FR-41.** `samples/` — 3–5 open-access научных PDF.

## 6. Нефункциональные требования (NFR)

| ID | Категория | Требование |
|----|---|---|
| NFR-1 | Производительность | Индексация 20-стр. PDF ≤60 с на CPU |
| NFR-2 | Производительность | TTFB чата ≤3 с (p95) |
| NFR-3 | Производительность | Ответ 300 токенов ≤15 с (p95) |
| NFR-4 | Производительность | Дашборд ≤1 с |
| NFR-5 | Надёжность | Падение LLM не блокирует загрузку следующего PDF |

## 7. Граничные случаи и риски

### 7.1. Граничные случаи
1. Скан-PDF без текстового слоя → явный `failed` + подсказка про OCR.
2. Двухколоночная вёрстка → pypdf может перепутать порядок; fallback pdfplumber.
3. PDF >200 стр → warning.
4. Смешанные языки RU+EN → мультиязычный эмбеддер.
5. 10 больших PDF одновременно → concurrency воркера = 2.
6. Удаление статьи во время индексации → cancel-флаг + каскад.
7. Повторная загрузка после удаления → разрешена (SHA пересчитывается).
8. Вопрос >2000 токенов → truncate + warning.
9. Статья без года → «Unknown» в аналитике.
10. Клик по цитате удалённой статьи → 404-handling + toast.


### 7.2. Риски и митигации
| ID | Риск | Вероятность | Влияние | Митигация |
|----|------|---|---|---|
| R-1 | OpenAI недоступен / нет ключа | Средняя | Высокое | `LLM_PROVIDER=ollama` fallback; пре-кэшированные саммари в samples; инструкция в README |
| R-2 | pypdf ломается на «экзотических» PDF | Высокая | Среднее | Fallback pdfplumber; проверенные PDF в samples/ |
| R-3 | Дрейф breaking changes LangChain/LangGraph 1.x | Средняя | Среднее | Зафиксировать версии; минимизировать абстракции (прямые LiteLLM + qdrant-client) |
| R-4 | Расхождение эмбеддеров индексация/запрос | Низкая | Критическое | Единый `EMBEDDINGS_PROVIDER`; проверка размерности при старте |
| R-5 | Docker build на Windows (volume paths, line endings) | Средняя | Высокое | Тест compose на Windows; относительные `./data`; `.gitattributes` `* text=auto eol=lf` |
| R-6 | Qdrant без named volume теряет данные | Низкая | Среднее | Named volume `qdrant_data`; `docker-compose down -v` = reset |
| R-7 | Стоимость OpenAI на больших статьях | Средняя | Низкое | `text-embedding-3-small`; кэш саммари; лимит 6 чанков×500 токенов |
| R-8 | SSE блокируется nginx-буферизацией | Средняя | Среднее | `X-Accel-Buffering: no`, `proxy_buffering off` в nginx.conf |
| R-9 | TypeScript 7.x — свежая major, плагины не совместимы | Средняя | Низкое | Зафиксировать TS ~5.6.x LTS-линейку |

## 10. Критерии приёмки
1. `git clone && cp .env.example .env` (добавить OPENAI_API_KEY) → `docker-compose up --build` — 4 сервиса без ошибок ≤5 мин.
2. `http://localhost:3000` → Чат empty-state по DESIGN.md.
3. Загрузка 3 PDF из samples/ → статус `indexed` ≤3 мин.
4. Вопрос по статье → streaming + ≥2 кликабельные цитаты `[1][2]` с верной статьёй/страницей.
5. Карточка статьи → Саммари 5 секций; повторно — мгновенно (кэш).
6. Аналитика → 4 непустых виджета.
7. Удаление статьи → счётчики уменьшаются, по ней нет ответов.
8. Битый PDF → понятная ошибка, приложение живо.
9. Нет сети → осмысленная ошибка UI.
10. Все 4 экрана соответствуют DESIGN.md (монохром, Geist, радиусы, красный только ошибки).
11. `pytest` в backend-контейнере: ≥60% покрытие критичных модулей, ≥5 интеграционных тестов.
12. README: quickstart, скрины 4 экранов, 3–5 примеров Q&A, раздел «Дизайн-система» + ссылка на DESIGN.md.
13. ARCHITECTURE.md ≤500 слов, ASCII, обоснование Qdrant vs pgvector/Chroma/Weaviate.

## 11. Допущения
- Один пользователь, без аутентификации.
- Файлы в локальной ФС (named volume), без S3.
- OpenAI — основной LLM-провайдер; Ollama — опциональный fallback.
- OCR вне скоупа.
- UI на русском; PDF могут быть англоязычными.
- Нагрузка: до 100 статей, до 10 одновременных загрузок, до 1 RPS чата.
- Проверяющий работает на Windows/macOS/Linux с Docker Desktop.
- Дизайн-референс DESIGN.md обязателен к реализации «как есть».
