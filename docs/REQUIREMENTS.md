# REQUIREMENTS — AI-native редактор проектного плана (Гант + чат)

> Источник: `ТЗ fullstack.pdf` (дословно извлечён в `docs/TZ_TEXT.txt`)
> Дизайн-референс UI: `DESIGN.md` (монохромная светлая тема, Geist, радиусы 18/24 px)
> Дата анализа: 2026-08-27. Статус: на согласовании.

---

## 0. Контекст и режим работы

- **Тестовое задание:** Full-stack разработчик AI-native продукта (React + FastAPI).
- **Режим:** демо-приложение, развёрнутое и доступное по ссылке; дополнительно локальный запуск через Docker Compose. Single-user, без аутентификации.
- **Сценарий одного экрана:** пользователь открывает страницу и сразу видит интерактивную диаграмму Ганта с **закешированными тестовыми данными**; рядом — чат для массового редактирования плана; изменения мгновенно отражаются на диаграмме; план экспортируется в Excel.

---

## 1. Цель и образ результата

Интерактивный планировщик проектов с **диаграммой Ганта как центральным элементом**. Пользователь:

1. открывает страницу и сразу видит Гант с тестовым проектом (без загрузки);
2. может загрузить свой Excel со списком задач;
3. через чат на естественном языке массово правит план: **переносит/сдвигает задачи, меняет зависимости, добавляет новые, перераспределяет исполнителей**;
4. правки агента мгновенно отражаются на диаграмме;
5. кликает по задаче → модалка с деталями (состав решаем сами);
6. экспортирует итоговый план обратно в Excel.

Успех приёмки: проверяющий открывает развёрнутую ссылку, видит Гант, пишет в чат «перенеси задачи на неделю позже / добавь задачу / сделай X исполнителем», наблюдает обновление диаграммы и скачивает обновлённый `.xlsx` за 5–10 минут без ручной настройки.

## 3. Пользовательские истории (User Stories)

Приоритеты: **P0** — must-have (приёмка), **P1** — should-have, **P2** — nice-to-have.

### 3.1. Гант и тестовые данные
- **US-1 (P0).** Как PM, я хочу видеть **сразу при открытии** интерактивную диаграмму Ганта с закешированной тестовой выборкой задач (задача, описание, исполнитель, длительность, предшественники), чтобы понять продукт без подготовки.
- **US-2 (P0).** Как PM, я хочу, чтобы на диаграмме были видны: шкала дат, полоса каждой задачи (от раннего старта до раннего конца), зависимости-стрелки, цвет/подпись по исполнителю или по критическому пути.
- **US-3 (P0).** Как PM, я хочу кликнуть по задаче → модаль с деталями: описание, исполнитель, длительность, предшественники, вычисленные даты старта/конца, всё редактируемое и кнопка «Сохранить».

### 3.2. Загрузка и валидация Excel
- **US-4 (P0).** Как PM, я хочу загрузить свой `.xlsx` со списком задач, чтобы строить Гант по своим данным.
- **US-5 (P0).** Как PM, я хочу, чтобы строка без существующих колонок `задача/описание/исполнитель/длительность/предшественники` давала понятную ошибку с указанием, какой колонки не хватает.
- **US-6 (P1).** Как PM, я хочу загрузку в форматах `.xlsx` и `.csv`, чтобы не зависеть от экселя.

### 3.3. Чат и массовое редактирование (центральный сценарий)
- **US-7 (P0).** Как PM, я пишу в чат на естественном языке, напр. «перенеси все задачи на 2 недели позже», «задача “Дизайн” начинается после “Аналитика”», «добавь задачу “Тестирование”, длительность 5 дней, исполнитель Иван, после “Разработка”», «переназначь “Сборка” на Петра» — агент **массово** правит план и **мгновенно** обновляет Гант.
- **US-8 (P0).** Как PM, я хочу, чтобы ответ чата стримился и в нём было объяснение «что изменено» (sделл + список затронутых задач) по-русски.
- **US-9 (P0).** Как PM, я хочу, чтобы изменения (сдвиг/каскад дат, новая зависимость, х новый исполнитель) отражались на диаграмме без перезагрузки — SSE-пуш состояния сессии.
- **US-10 (P1).** Как PM, я хочу кнопку «Отменить последнее изменение» (undo), чтобы вернуться к предыдущему состоянию плана.

### 3.4. Движок расписания
- **US-11 (P0).** Как PM, я хочу, чтобы при любой правке даты автоматически пересчитывались по правилам: задача начинается не ранее завершения всех предшественников; сдвиг задачи двигает и зависимые (каскад); критические задачи видны.
- **US-12 (P1).** Как PM, я хочу получать предупреждение, если правка создаёт цикл зависимостей или переносит задачу в выходные/прошлое.

### 3.5. Экспорт и UI
- **US-13 (P0).** Как PM, я хочу экспортировать текущий план обратно в Excel с теми же колонками `задача/описание/исполнитель/длительность/предшественники` (+ вычисленные даты).
- **US-14 (P0).** Как PM, я хочу, чтобы весь UI соответствовал DESIGN.md (монохром shadcn/ui, Geist, радиусы 18/24, красный `#e7000b` только для деструктивных действий), с корректными loading/empty/error-состояниями.

## 4. Use Cases

### UC-1. Открытие и просмотр Ганта с тестовыми данными
**Актор:** PM.
**Предусловие:** рендер фронтенда доступен, бэкенд встал.
**Основной поток:**
1. Пользователь открывает приложение.
2. Frontend запрашивает `GET /api/session/{sid}/state`; если сессии нет — `POST /api/session` создаёт новую сессию и наполняет её закешированной тестовой выборкой.
3. Backend возвращает: список задач с `naименование/описание/исполнитель/длительность` и **вычисленный расписанием** `начало/конец`, зависимости, критический путь.
4. Frontend рендерит диаграмму Ганта + задачи с модалкой.
**Постусловие:** диаграмма видна без ручной загрузки.

### UC-2. Загрузка собственного Excel
**Актор:** PM.
**Предусловие:** активная сессия.
**Основной поток:**
1. Пользователь выбирает/перетаскивает файл → `POST /api/session/{id}/upload` (multipart, .xlsx/.csv).
2. Backend: `openpyxl data_only=True` читает значения (без формул/макросов), сопоставляет колонки `задача/описание/исполнитель/длительность/предшественники`, парсит предшественников (по именам или индексам), валидирует.
3. Движок расписания считает даты; заменяет задачи сессии.
4. Frontend обновляет Гант.
**Альтернативы:** A1 отсутствует строка (напр. `длительность`) → 400 с именем колонки; A2 некорректные предшественники → предупреждение + задача без даты; A3 пустой лист → 400 «нет данных».

### UC-3. Массовая правка через чат (центральный)
**Актор:** PM, LLM, Движок расписания.
**Предусловие:** в сессии есть задачи.
**Основной поток:**
1. Пользователь пишет команду, напр. «перенеси финальные задачи на неделю».
2. Frontend открывает SSE `POST /api/session/{id}/chat/stream`.
3. Backend: сбор контекста (схема плана, список задач с датами, history, последние tool-результаты) → **первый вызов LLM** — строгий structured-output `Intent {action, targets, params, explanation}` (pydantic).
4. `policy.py` классифицирует (простое/деструктивное/массовое).
5. **Выполнение через MCP**: агент вызывает инструмент (`shift_tasks`, `set_dependency`, `add_task`, `reassign`, `edit_field`, `remove_tasks`…) → инструмент мутирует план через `SessionStore`; **движок расписания пересчитывает каскад дат**; возвращает `{ok, affected, diff}`.
6. Frontend сразу получает SSE-событие `plan` (самое положение дат) → **Гант мгновенно перерисовывается**.
7. **Второй вызов LLM** — стриминговый: объяснение по-русски (SSE `delta`).
8. Если операция деструктивная/массовая — ставится в `pending`, фронт показывает `ConfirmModal` («Подтвердить/Отменить»).
**Альтернативы:** A1 — намерение не распознано/нет инструмента → агент уточняет у пользователя; A2 — некорректный JSON intent → 1 retry затем ЧВ-ответ «уточните»; A3 — LLM недоступен → понятное сообщение, план не ломается.
**Постусловие:** план изменён, диаграмма обновлена, кнопка undo активна.

### UC-4. Экспорт
**Актор:** PM.
**Поток:** кнопка «Экспорт» → `GET /api/session/{id}/export?format=xlsx|csv` → значения задач + вычисленные даты, `Content-Disposition: attachment`. Имя файла sanitise.

### UC-5. Модаль задачи (details — наше решение)
Состав: название, редактируемое описание, исполнитель, длительность (дни), предшественники (мультиселект по названиям), вычисленные даты старт/конец, индикатор критического пути, кнопки «Сохранить» (правка через MCP/каскад) и «Удалить» (если деструктивная — подтверждение).

## 5. Функциональные требования (FR)

### 5.1. Гант и сессия
- **FR-1.** `POST /api/session` → создаёт сессию и **заваливает тестовые данные** (кешированные, ~8–12 задач, реалистичная структура с зависимостями).
- **FR-2.** `GET /api/session/{id}/state` → `{schema, tasks: [{id,name,description,assignee,duration,predecessors,start,end,critical}], plan: {total_days, critical_path[]}, pending, version_head}`.
- **FR-3.** Гант-рендер: лента времени (дни/недели), бар каждой задачи (start..end), стрелки зависимостей, цвет по исполнителю или критическому пути (по DESIGN.md).

### 5.2. Excel import/export
- **FR-4.** `POST /api/session/{id}/upload` — multipart, `.xlsx`/`.csv`, ≤20 МБ; строго `задача/описание/исполнитель/длительность/предшественники`; `openpyxl data_only=True` (без формул/макросов); значения валидируются.
- **FR-5.** Ошибки формата: 400 с именами отсутствующих колонок; 413; неверные предшественники — предупреждение.
- **FR-6.** `GET /api/session/{id}/export?format=xlsx|csv` — те же 5 колонок + вычисленные `начало/конец`; безопасное имя файла; Content-Disposition.

### 5.3. Чат-правка (MCP + LLM)
- **FR-7.** `POST /api/session/{id}/chat/stream` (SSE): события `intent` → `update` → `delta` (metть наррация) → `pending`? → `done/error`.
- **FR-8.** Первичное намерение: полуструктурированный JSON строгий (pydantic); ошибка распарсивания → 1 retry → Уточнение.
- **FR-9.** Действия LLM выполняются строго через **MCP-инструменты** (см. §Arch), LLM к данным доступа через точечные вызовы, не весь план целиком.
- **FR-10.** Поддерживаемые действия: `shift_tasks` (сдвиг всех/выбранных на N дней/недель/к дате), `set_dependency` (добавлять/удалять прешеств), `add_task`, `remove_tasks`, `reassign` (исполнитель), `update_field` (название/описание/длительность), `undo`, `help/schema`.
- **FR-11.** `policy.py`: удаление, массовое изменение, сдвиг больших групп → `pending` + подтверждение; единичная правка — сразу.
- **FR-12.** Two-pass: intent (не стриминг) + наррация (стриминг). Объяснение «что изменилось» на русском.
- **FR-13.** После каждой правки — каскадный пересчёт расписания и мгновенный пуш `update` на фронт.

### 5.4. Движок расписания
- **FR-14.** Топологическая сортировка + forward pass: `start(T) = max(start(P)+dur(P))` по предшественникам; `end = start + dur`. День 1 = первый рабочий день проекта.
- **FR-15.** Критический путь (longest chain, backward pass то ли ранних) → флаг `critical` на задачи.
- **FR-16.** Выявление циклов зависимостей → ошибка/предупреждение, правка отклоняется.

### 5.5. MCP-слой
- **FR-17.** Встроенный MCP-сервер (SDK v2 `MCPServer`) регистрирует инструменты; LLM-агент — MCP-клиент.
- **FR-18.** Инструменты не знают про REST; выносимы в отдельный процесс на проде.
- **FR-19.** `compute` (сумма/сред./мин./макс./медиана + длительность по исполнителям) — whitelist, без `eval`/`exec`.

### 5.6. UI (DESIGN.md)
- **FR-20.** Строгое соответствие DESIGN.md: токены, Geist, радиусы 18/24, красный только destructive.
- **FR-21.** Один экран: слева Гант (центр), справа чат, сверху тулбар (upload/undo/versions/export), модаль задачи, ConfirmModal.
- **FR-22.** loading-skeleton, empty-state, error-state с retry.

### 5.7. Ops / Deliverables (фактическое ТЗ)
- **FR-23.** README: запуск (локально + развёрнуто), архитектура, принятые решения, **отдельный раздел «Как использованы AI-ассистенты при разработке»**.
- **FR-24.** **Демо-gif** «загрузка Excel → правка чатом → экспорт».
- **FR-25.** **Пример Excel** в `samples/` (тестовая выборка).
- **FR-26.** **`ROADMAP_TO_PRODUCTION.md`**: техдолги, чего не хватает для проде, риски, порядок закрытия.
- **FR-27.** **Ссылка на развёрнутое приложение** (Render/Vercel/Fly.io/VM) в README.
- **FR-28.** Ссылка на **git-репозиторий** (версия: локальный запуск + развёрнутая ссылка из ТЗ, репозиторий публикуется по согласованию).

## 7. Граничные случаи и риски

### 7.1. Граничные случаи
1. Цикл предшественников («A после B», «B после A») → отклонение + понятное сообщение.
2. Задача без предшественников → старт с начала проекта.
3. Неизвестный исполнитель — создаём свободную строку (оставляет как есть).
4. Двузначный «длительность» / пустая длительность → предупреждение, default 1 день.
5. Сдвиг в «прошлое»/выходные — допускается, но предупреждаем.
6. Сдвиг задачи двигает зависимых каскадом (документально ошибка № 1, если каскад не ожидал).
7. Сессия пустая (после удаления всех задач) → пустой Гант + CTA «добавь задачу».
8. LLM вернул действие над несуществующей задачей → тихой игнор + «задача не найдена».

### 7.2. Риски и митигации
| ID | Риск | Вер | Влияние | Митигация |
|----|------|---|---|---|
| R-1 | Бесплатный хостинг усыпляет (Render) / истёк срок | Сред | Выс | Render free + ожидание при первом запросе; инструкция как поднять локально за 1 команду. |
| R-2 | LLM провайдер без ключа | Сред | Выс | `LLM_MODEL` из env, понятное сообщение; intent-парсер можно проверить настроенными сценариями. |
| R-3 | Дрейф MCP SDK v2 (28.07.2026) | Низ | Выс | Зафиксировать mcp==2.0.0; in-process изоляция (нет сетевых точек отказа в демо). |
| R-4 | Custom Гант «не тянет» интерактив | Низ | Сред | Держать рендер простым (CSS grid), декомпозиция уже проработана; fallback на библиотеку при необходимости. |
| R-5 | Каскад при сдвиге — неожиданные изменения | Сред | Выс | Юнит-тесты движка расписания (топосортировка+forward pass) как обязательный гейт. |
| R-6 | Секреты/env утекают на git | Очень Низ | Критич | `.env.example` только; `.gitignore` исключает `.env*`. |
